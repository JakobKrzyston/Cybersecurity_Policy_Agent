  Slice 6 Plan: Mock Tool Registry + Tool Executor

  What needs to be built

  1. Mock tool implementations (src/tools/) — each tool currently raises
  NotImplementedError. They need to return predictable dicts for tests to assert
   against.

  2. Tool Executor (src/pipeline/tool_executor.py) — the current stub needs to
  become real. The interface needs to expand to include trust context:

  def execute(
      decision: ReasonerDecision,
      trust_tier: str,
      risk: str,
      tracer,
  ) -> list[dict]  # e.g. [{"tool": "reset_password", "result": {...}}]

  The executor: (a) checks trust/risk per tool call, (b) looks up the tool in
  the registry, (c) calls it, (d) passes raw result through the Output Filter.

  Behaviors to test (in order)

  1. Registered tool is executed and returns result — tracer bullet, proves
  end-to-end path works
  2. Unregistered tool name is refused — registry enforcement
  3. Red risk blocks all tools except escalate_to_human — safety invariant from
  CONTEXT.md: "red → only escalate_to_human reachable"
  4. All tool calls in a decision are processed — multiple tools in one decision
  5. Empty tool_calls returns empty list — degenerate case

  The Output Filter is still a stub (Slice 7), so the executor will call it but
  tests won't assert on filtered output yet — just that it runs without error.

  Questions

  1. Should an unregistered tool name raise an exception or silently skip? (I'd
  lean raise, since it indicates a Reasoner hallucination that Citation
  Grounding should have caught.)
  2. For red risk + non-escalate_to_human tool: raise or skip + log?
  3. Should the registry be injectable (passed as a parameter) or module-level 
  constant — for test isolation do you want to be able to swap in a test
  registry, or test against the real one?
