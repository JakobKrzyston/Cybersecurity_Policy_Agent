  Plan: Slice 3 — Policy Retriever

  What we're building

  Three distinct responsibilities, each testable independently:

  1. Chunker — parse gaggia_helpdesk_policy.md into clause-level PolicyChunk
  objects (pure function, no I/O)
  2. ChromaDB retriever — embed chunks, run semantic + tag-filtered queries
  (in-process ChromaDB, no external services)
  3. Cross-reference expander — one-hop expansion gated by tag intersection
  (pure function)

  Public interface (what tests will use)

  @dataclass
  class PolicyChunk:
      id: str     # e.g. "1.1.b"
      text: str   # prefixed with section header + tags + related sections
      tags: list[str]

  class PolicyRetrieverBase(ABC):
      def retrieve(self, query: str, tags: list[str] | None = None, top_k: int =
   5) -> list[PolicyChunk]: ...

  # concrete implementation
  class ChromaDBRetriever(PolicyRetrieverBase): ...

  No other module imports chromadb directly.

  Behaviors to test (in this order)

  #: 1
  Behavior: Chunking section 1 produces a chunk with id "1.1.b" (tracer bullet)
  Component: chunker
  ────────────────────────────────────────
  #: 2
  Behavior: Every chunk text is prefixed with its parent section header, tags,
    and related sections
  Component: chunker
  ────────────────────────────────────────
  #: 3
  Behavior: Section-level headers (e.g. "1") also get chunks
  Component: chunker
  ────────────────────────────────────────
  #: 4
  Behavior: Retriever returns PolicyChunk objects with both id and text
  Component: retriever
  ────────────────────────────────────────
  #: 5
  Behavior: Querying for "password reset" returns chunks from section 1
  Component: retriever
  ────────────────────────────────────────
  #: 6
  Behavior: Tag filter narrows results to chunks sharing that tag
  Component: retriever
  ────────────────────────────────────────
  #: 7
  Behavior: Cross-reference expansion includes a related section only when it
    shares a tag
  Component: expander
  ────────────────────────────────────────
  #: 8
  Behavior: Cross-reference expansion excludes related sections with no
    overlapping tags
  Component: expander

  Files to create/modify

  - src/pipeline/policy_retriever.py — PolicyRetrieverBase, ChromaDBRetriever,
  retrieve()
  - src/infra/embeddings.py — get_collection() helper
  - New: src/pipeline/chunker.py — chunk_policy() pure function
  - New: tests/test_policy_retriever.py

  One question before we start

  For the retriever integration tests (behaviors 4–6), ChromaDB needs an
  embedding function. Options:

  - Option A: Use ChromaDB's default embedding (downloads a small
  sentence-transformers model on first run — ~90MB, slow first run but no
  mocking)
  - Option B: Use ChromaDB's embedding_functions.DefaultEmbeddingFunction with a
   stub that returns random vectors (fast, but test 5 "password reset returns
  section 1" would be probabilistic)
  - Option C: Use TF-IDF / keyword cosine similarity for tests only, swap real
  embeddings in production via the abstraction layer

  My recommendation is Option A — accept the one-time download cost. Tests 4–6
  then verify real retrieval quality, not just "does something come back." This
  matches the integration-style testing philosophy.
